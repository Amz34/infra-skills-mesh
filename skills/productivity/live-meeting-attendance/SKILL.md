# Live Meeting Attendance (join + capture + notes for the user)

## When to Use
User shares a meeting link and cannot be there: "attend this for me", "meeting me meri taraf se baith jao", mastermind/webinar/discovery call, or they want a transcript + notes without recording it themselves. Also for capturing a live webinar/demo for research.

## Ground Rules (do these BEFORE joining)
- **Silent notetaker.** Mic/cam off, no chat messages, no poll answers, no hand-raise. Poll/DM answers belong to the user — never invent them.
- **State the limits up front**: a headless VM has no working mic, so you can listen but not speak/answer. Say this in the report so the user is never surprised.
- **Credential hygiene**: meeting join links carrying `tk=` / `pwd=` / `uuid=` are bearer credentials. Never echo, log, store, or leave them inside scripts under `~/ops` — pass via env var, and treat response-header dumps (e.g. `/tmp/<svc>_hdr.txt`) as sensitive.
- **Display-name honesty**: a token link carries the name baked into it; you cannot change it and cannot reliably see what others see. Try to read the self-tile/participant list; if unverified, tell the user it is unverified instead of asserting a name.
- **Who the speaker IS is a claim to verify, never to inherit (Aamir correction, 2026-09-20).** On the DDS "Master Agentic AI" lane the brief named the wrong host — a stale name carried over from the previous run's notes/label file, reinforced by the loudest name in `chat.txt`. The real host was **Mohammad Arshad** (Founder DDS, Dubai), visible in the registration confirmation, the event/Q&A-board page and the event's LinkedIn — none of which the brief consulted. Rules: (a) take the host from an **authoritative artifact** — registration confirmation / calendar invite / event page / Q&A board / the event's LinkedIn — never from ASR captions, never from `chat.txt`, never from a previous session's notes file; (b) in a webinar **chat is dominated by attendees**: a name repeated 5× in chat is a *questioner*, not the speaker — questioners ≠ speakers; (c) record it in the notes-file header as `host: <name> (verified via <source>)`, so the next wrap-up cannot re-inherit a wrong name; (d) when the user corrects an identity, treat it as authoritative and fix the **notes FILE** too (not just the chat reply), then grep the transcript for both names before restating anything.
- **If the host calls the user's name** (roll call, shout-out, "Aamir, are you with us?"): the only workable response is a **typed chat message** — a webinar attendee can message Hosts & Panelists only, this VM has no audio input device so speaking live is impossible, and voicing someone else's identity is off-limits. Default is to stay silent: silence exposes nothing, since the attendance itself is silent. Arm detection in the monitor (`MENTIONS=` grep for the user's and the client's names over captions **and** chat) so the alert carries the exact line, and ask once up front whether they want a ready-to-send chat reply or alert-only. Also offer a display-name check — a call-out can only match if the joined name is right.
- **Read the chat panel before the meeting ends.** Organisers drop document/slide links in chat and often mail them later ("we will share the links via mail later"), so harvest what is there while the session is live. An unwritten/failing `chat.txt` does **not** mean chat is unreadable: read the open panel's DOM directly over CDP.
- User's language for the chat report (Hinglish for Aamir), pure English for any notes FILE.

## Pipeline (defence in depth — three independent captures)
1. **Audio** (highest value if captions are off): whatever the browser plays lands in the default/null sink; record `<sink>.monitor` with ffmpeg: `-f pulse -i <sink>.monitor -ac 1 -ar 16000 -f segment -segment_time 300 -reset_timestamps 1 out_%03d.wav`. **Then verify the file has signal** — growing segments and an `active` unit prove nothing: `ffmpeg -sseof -5 -i <seg>.wav -af volumedetect -f null -` → `max_volume: -91.0 dB` means digital silence. `scripts/zoom_audio_check.sh` runs that check plus a sine-tone round-trip that tells "chain broken" apart from "source silent".
2. **Live captions**: the web client renders captions in the DOM; poll the subtitle node and log only deltas (prefix-diff) to `captions.txt`. Cheap, near-real-time, but only exists while the host has captions on.
3. **Screenshots + chat**: periodic full-page shots (slide/screen-share text usually lives only in the pixels) plus chat-panel text to `chat.txt`.

Then a **chunked local-whisper transcriber** (low priority) converts each closed audio segment into `transcript.txt`, so a real transcript exists even when captions never appear.

## Zoom web-client render shapes — drive the FRAME, not the page (verified 2026-09-17)
The client is not always in the top document. Two shapes seen on the same shard:
- `…/wc/<mn>/join?action=join&confno=<mn>&browser=chrome&tk=<short>` → client renders in the **main frame** (plain `document.querySelector` works).
- Registration-link flow: `/meeting/register/<id>` → SPA form (`#question_first_name`, `#question_last_name`, `#question_email`, `#question_phone`, filled with CDP `Input.insertText`) → redirect to `…/wc/<mn>/join?ref_from=launch&tk=<JWT>` — the top document is a **stub** (≈"You are about to join…") and the whole meeting UI (toolbar, Join, participants, captions) lives **inside an iframe**. Symptom of ignoring this: every probe answers "no buttons / NOJOIN / empty list" while tab title and URL look perfectly right.

Fix: walk `Page.getFrameTree`, pick the **deepest** frame whose `url` contains the meeting number (several frames carry it — deepest match wins), open a world in it, then evaluate/click there: `Page.createIsolatedWorld(frameId=…, worldName='z')` → `Runtime.evaluate(expr, contextId=ctx, returnByValue=True)`. In-frame `el.click()` **does** work for Join / Show Captions / audio controls. `scripts/zoom_frame_eval.py` wraps all of it (`frames|text|js|click`).

Join flow that works end to end: open the stored `/w/<mn>?tk=…&uuid=…` (or the registration `ref_from=launch` URL) → click "Join from browser" in the main frame → the client auto-joins when the `tk` is valid, otherwise shows the preview → in the deepest frame click `^Join$` (preview showing `Mute` / `Start Video` = mic muted / cam off ✓). Never hand-build a join URL: a registration JWT `tk` pasted into the `action=join` form leaves the Join button styled `disabled` (property `disabled === false`) and adds a bogus "Meeting Passcode" field — a red herring that costs an hour.

## Two meetings at once (multi-lane: "open the other tab too")
Run each meeting as an independent lane instead of reusing one run dir:
- Per-lane config `~/.config/zoom-attend/current<N>.env` (`ZOOM_RUN`, `ZOOM_TAB_KEY`, `ZOOM_FRAME`), per-lane run dir, per-lane units (`zoom2-*`), and scripts patched **once** to read `RUN = os.environ.get("ZOOM_RUN", <default>)` + `ZOOM_FRAME` at import — a lane then never needs a code edit.
- **One lane gets clean audio; the second falls back to attendance + captions.** In one Chrome, an audio-device change drops a client's `<audio>` element (pitfall below) and moving one meeting's element to a dedicated sink can blank the other's — chasing both ends in ping-pong where each fix breaks the other lane. Keep the priority meeting on the default sink, park the secondary meeting's elements on a secondary sink so they cannot leak into the primary recording, and capture the secondary from its captions.
- Per-meeting sink when it is needed: `pactl load-module module-null-sink sink_name=X sink_properties=device.description=X` → inside that meeting's frame take the deviceId from `navigator.mediaDevices.enumerateDevices()` whose `label` equals the sink name → `el.setSinkId(deviceId)` for **every** audio element of that tab (a stray `sinkId='default'` element leaks the meeting straight back into the primary lane) → confirm with RMS on `X.monitor`.
- **Bind each watcher to its own meeting number.** A generic `TAB_KEY=app.zoom.us/wc/` matches ANY Zoom tab, so the watcher never sees "its" tab vanish and can rejoin the wrong meeting.
- Say the registration identity back to the user (name/email/phone are their PII and theirs to change).

## Durability: systemd --user units, not ad-hoc background terminals
Sessions and context windows end; meetings outlive them. Run three user units (`zoom-attend-recorder|scraper|transcriber.service`) with `Restart=on-failure` and `WorkingDirectory=~/ops/<name>/run/`. Verify with `systemctl --user is-active` plus a byte/line growth check — not by trusting the start command.

## End-of-meeting automation (no babysitting)
One Hermes cron job, every 5 min, using **monitor_script** with stable output:
```
STATE=LIVE|ENDED
CAPTION_LINES=<n>
MENTIONS=<n>
MENTION: <deduped line matching user/client name>
```
Unchanged output ⇒ the tick is suppressed entirely (no LLM, no message). Changed ⇒ the agent runs and finalizes: stop units, transcribe leftovers, write the notes file, deliver the summary. Mention lines give the user an instant alert if their name/client is raised. Same shape as the cron-watchdog pattern.

### Wrap-up of an AUDIO lane — trust the waveform, not the flag (verified 2026-09-17)
The masterclass lane (`run-masterclass-0917`) ended with the UI flag, the captions and the audio telling three different stories. The order of operations that produced a trustworthy report:
1. **Find the real end from audio level, not `run/ENDED`.** `ENDED` said `16:11:12`; substantive speech actually ran to `16:17:48` (the last chore-bearing chunk) and the tail from `16:18:43` measured `mean_volume -87.3 dB / max_volume -41.5 dB` = digital silence. Finalize on level evidence and state the flag's error (here ~7 min early; the watchdog's `announced_end` was `16:15:59`).
2. **Decide which stream is the record of record by counting, after the fact.** This lane: `captions.txt` = 7 lines / ~22 s (the scraper died at the false END) vs `transcript.txt` from the audio lane = the whole session — the *inverse* of the usual "no audio" case. Measure both (line/char counts), then say which one carried the content.
3. **Transcribe the last *closed* chunk before stopping anything.** The transcriber loop skips `files[-1]` by design, so a chunk that closed seconds before wrap-up is silently missing; invoke the same whisper wrapper by hand on it — but gate it on `volumedetect` first, so silence is not converted into prose.
4. **Count the gaps, never claim "full capture".** `ffprobe -show_entries format=duration` on every segment plus the start time baked into the filename (`live_%Y%m%d-%H%M%S.wav`) gives coverage in one pass: this run = 15 chunks, 4159 s audio / 4413 s span = **94.2 %**, 14 boundary gaps totalling 254 s (largest 54.9 s). That number belongs in the notes file; "silence in ⇒ invented text out" makes a claimed 100 % look fabricated.
5. **OCR the screenshots for every number, model id and identifier.** ASR mangles exactly the facts a wrap-up needs: "Salesforce"→"Seattle", `moonshotai.kimi-k2.5`→"kin k2.5 / you scheme", Kubernetes→"cupartinos", ₹18,000→"80,000 rupees", ₹→"one like". One loop, `for s in shots/*.png; do tesseract "$s" - --psm 6; done` (61 shots), verified the model id `BedrockModel(model_id="moonshotai.kimi-k2.5", region_name="us-east-1")`, the S3 bucket `manufacturing-scm-august-2026` / `ap-southeast-1`, and the pricing `20,000→18,000`, `40,000→30,000`, `enrollment 15,000`. **Store the OCR text as `run/<lane>/shots-ocr/*.txt`** so the notes' evidence is reproducible without re-transcribing.
6. **Treat the tail as off-record.** The final chunk contained "The recording has stopped. … can you please just not send it to the chat?" — a conversation the presenters believed was private, captured only because the recorder outlived the content by ~19 min. Quote the end-of-recording line at most as end-time evidence, never circulate the body, and stop the recorder at the confirmed end: a `Restart=always` unit happily writes megabytes of digital silence (and `stop` can leave it in `failed` → `systemctl --user reset-failed`).
7. **Stop only your own lane's units.** Lane 1 (a different meeting, `run/`, id 85420434468) was left running deliberately and merely flagged in the report — a wrap-up cron must not close a lane it does not own.

## Autonomy + the "abhi kya position hai?" ping
- "Khud karlo / you attend for me / fast + smooth" = execute end to end without asking for confirmation. Only credential- or OTP-shaped steps come back to the user. Do not re-ask what was already authorised.
- The user will interrupt mid-meeting with a short status question. Answer from **freshly verified** signals, not from the last snapshot you remember — re-read the run dir and (if cheap) grab one screenshot. Answer shape that works, tight and in the user's language:
  1. one-line verdict (`LIVE hai, main andar hoon` + local time);
  2. meeting name/day + who is speaking + what is on screen right now (slide title / shared-window content);
  3. capture evidence with numbers (caption lines + timestamp of the last one, shots count, audio state);
  4. interaction status: poll open (0/N answered by me), chat silent, mic/cam off — so the user knows nothing was done in their name;
  5. any honest gap (e.g. audio silent, display name unverified) + what happens at the end (notes file + summary reach them).
- Never let a status reply imply more capture than is verified: quote counts you just measured, and name the gap in one line rather than hiding it.

## Answering "ab tak ka conclusion/notes kya hai?" while the meeting is still LIVE
Mid-meeting there is no final conclusion: deliver **the framework/decisions taught so far + what to do next**, never a verdict and never a wall of text.

**0. Locate the LIVE lane before reading anything (2026-09-20).** The live files sit in the lane's `ZOOM_RUN` dir — default `~/ops/zoom-attend/run/`. Session-named dirs (`~/ops/zoom-attend/run-<ts>-<label>/`) and other toolkit paths (`~/ops/livecapture/runs/…`) may exist but can hold the **previous** session's audio/transcript, so a `ls` there answers a stale question. The authoritative "which meeting is being captured right now" is `run/label.txt` (with `run/source-url.txt`, `run/lang.txt`). One pass, in this order:
   - `grep -n '^=== live_' run/transcript.txt` → chunk headers `=== live_YYYYMMDD-HHMMSS.wav (HH:MM:SS) ===`. The filename stamp is the real session start (independent of label files) and each header is a timeline anchor; `awk '/^=== live_<ts>/,0'` or `tail -n +<lineno>` pulls one window.
   - `tail -3 run/transcriber.log` → the chunk currently in flight.
   - `tail -c 5000 run/chat.txt` → `[HH:MM:SS] Name To Meeting Group(Everyone): text`.
   - `ls -t run/shots/*.png | head -1` → the slide to attach.
   - `scripts/live_brief_sources.sh [RUN_DIR]` prints all of the above in one shot.

**Two clocks, two sources — bind the brief to the transcript, the news to the chat.** Transcription lags wall-clock by ~3–5 min (a chunk only reaches `transcript.txt` after it closes *and* whisper finishes, while `transcriber.log` already shows `transcribing <file>`), whereas `chat.txt` is near-real-time. So state the coverage horizon explicitly ("transcript abhi 09:06 tak hai"), build the topic narrative from the transcript, and take anything from the last few minutes — offer/pricing drops, Q&A-platform links, audience questions with names, attendee counts — from the chat tail. A lagging transcript must never be read as "nothing was said since". Group topics by the order taught, and keep the speaker's own numbers/tool names rather than paraphrasing them.

1. **Build it from the caption log, not from memory.** With audio silent, `captions.txt` IS the transcript of record.
2. **Dedupe before reading — with the script that already exists.** A whole-file read of a duplicated caption log burns context and can come back elided (empty output). Invoke the packaged tool by absolute path, `~/.hermes/skills/productivity/live-meeting-attendance/scripts/dedupe_captions.py <captions.txt> [HH:MM HH:MM] [--chars 110] [--limit N]`, instead of hand-writing dedupe code again (2026-09-17 was wasted on a re-implementation). It keeps the longest variant per timestamp in first-seen order, so you can pull one window at a time (e.g. `15:40 16:05`, then the tail) across a few small calls instead of one giant print. Zoom live captions repeat every line 2–4× with growing prefixes, so unique text ≈ 1/3 of `wc -l`.
3. **File carries the detail, chat carries the takeaways.** Write English notes to `~/ops/<name>/notes-<date>.md` with: header (meeting id, host, date, how attended, capture caveat) → *core thesis* → the step-by-step framework as taught (numbered, with the numbers/quotes they actually gave) → **action checklist** → host logistics (what will be mailed, who was removed, promises made) → **capture status**. **Refresh that file progressively while the session is live** (append/rewrite each time you answer a mid-session question) rather than writing it only at the end: it survives context compaction, and it *is* the source for the next "ab tak kya hai?" answer — the chat reply then costs no re-reading. Chat reply = the conclusion + the file path.
4. **Stop the dumps the moment they say so.** "Abhi nahi sari meeting [m]e do" / "bas important cheez batao" means: from now on ping only what is actionable (name mention, decision, link, end-of-meeting notes) and keep replies to a few lines — the notes file still gets everything.
5. **Logistics are part of the deliverable** — "links will be shared via mail later", a spammer removed from the room, materials promised: that is what the user needs after the fact, so capture it from chat/captions even when it is not "content".
6. **"Abhi tak ka kya summarize hai?" is a two-part answer, and the second part is easy to forget.** (a) *Session content so far* — grouped by topic, carrying the concrete numbers the speaker actually gave (tool names, amounts, timings), plus what is still on their stated roadmap; (b) *our side* — capture numbers you just measured, the artefacts that exist (notes file path), and the honest gaps in one line (e.g. "slides 0 files, transcriber 0 chunks — verify karna hai") + whether those gaps hurt the deliverable. Close with a single offer, not a question list. Bullets + Hinglish in chat, English in the file. Answer it from the notes file you have been refreshing, and never re-read the whole caption log to do it.

## Pitfalls (learned the hard way)
- **systemd eats `%`**: `live_%03d.wav` inside ExecStart is parsed as a systemd specifier → unit invalid. Escape as `live_%%03d.wav`.
- **Pin the interpreter that has the CDP websocket lib** (the Hermes venv python), not `/usr/bin/python3` — PEP 668 VMs have no `websocket` module there; the symptom is an instant unit restart loop.
- **Zoom caption selectors (verified 2026-09)**: `.live-transcription-subtitle__item` → `.live-transcription-subtitle__content`. Empty while nobody speaks is normal — treat empty as "quiet", not "broken". Dedupe consecutive identical lines or the ~4s poll floods `captions.txt`.
- **2-core VM**: whisper must be nice'd/pinned to one thread, or Chrome starves and capture stutters.
- **Keep tool-call arguments short** in this harness: very long command strings/heredocs can get cut mid-way, and a truncated `systemctl --user …` reached bash as a literal error. Prefer small files written in steps; read back what you wrote before relying on it. Seen again 2026-09-17: an inline `python3 - <<'EOF' … EOF` caption-dedupe heredoc was clipped mid-body and the script happily wrote a **short** output file (6 KB where the log held 48 KB of unique text) — the file looked valid, so the clipping is silent. Guard rails:
  1. Put anything longer than a couple of lines on disk with `write_file` and run the file (`python3 /tmp/<name>.py`) — never a big inline heredoc.
  2. Read a large text file in **slices with a short command**: `python3 -c "s=open('/tmp/x.txt').read(); print(s[9000:18500])"` — ~9 K chars per call is safe and prints reliably. In the same window `dd … | tail -c` and a bare `head -c` on the same file returned **empty output** with exit 0 (looks like "no such content"); that is an elision, not an empty file.
  3. Make the script print its own totals (`RAW_LINES / UNIQ_SEGMENTS / FULL_CHARS`) and compare them against the source (`wc -lc`) before you trust or summarise from the output.
- **Verify `transcript.txt` is growing, not just `transcriber.log`**: a `%s`-placeholder/arg-count bug in the whisper writer threw `loop error: not enough arguments for format string` every 20s while `transcriber.log` still showed `transcribing <file>`/whisper exits 0 — `transcript.txt` silently stayed 0 bytes. Fixed 2026-09-14 in `transcribe_chunks.py` (header `% (...)` was missing `txt`). After editing that script, `systemctl --user restart zoom-attend-transcriber` — the running unit keeps the old code and will not pick the fix up on its own.
- Don't re-join repeatedly with the original token if it may be single-use/expiring — check whether the first tab is still in the meeting before opening another.
- **"Unit active" ≠ "capturing".** Check the level inside the file (`volumedetect`), never the unit state or `du -sh`: a silent recorder happily writes megabytes.
- **Silence in ⇒ invented text out.** Whisper on a digital-silence segment hallucinates plausible sentences. If the audio check fails, stop the transcriber and move the bogus `transcript.txt` aside (`mv transcript.txt transcript.silence.bak`) instead of shipping it as notes.
- **The browser may render no audio at all.** Zoom's web client plays remote audio via WebAudio/WebRTC, so the page `<audio>` is `paused=true, src=none`; `.play()` on it does nothing and a trusted click doesn't revive it (this VM's Chrome has no `--mute-audio`, so that flag is not the cause). Do NOT restart Chrome to fix it — with a token link that can cost the whole attendance. Fall back to live captions as the transcript and report the limitation plainly. Detail + diagnosis: `references/zoom-webclient-capture.md`.
  **Update 2026-09-17 — the element CAN be live; `0` elements means it was DROPPED, not that the client cannot play.** In a healthy session `document.querySelectorAll('audio').length === 1` and `el.setSinkId(deviceId)` moves that live stream to a dedicated null sink (verified: RMS ~1900 on the sink monitor while the other lane stayed silent). So check element count + sink RMS *before* concluding "no audio possible", and only then fall back to captions. `paused=true, src=none` with count 0 is the dropped state below.
- **A live client loses its audio and still looks "in meeting" (2026-09-17).** Evidence: frame text still contains `leave`, participants list fine, captions still arriving — but `document.querySelectorAll('audio').length === 0` and the sink monitor measures RMS 0.0 (recorder writes digital silence while `transcriber.log` looks healthy). Captions ride the data channel, so **captions are not proof that audio is playing**. Triggers: joining a second meeting tab, creating a null sink, `setSinkId` on another tab, general tab churn. Recovery, verified ~15 s: `Page.reload` the tab → a `ref_from=launch` URL does **not** auto-rejoin, it lands on the pre-join preview (`Mute` / `Start Video` / `Join`) → click `^Join$` in the deepest frame → audio element is back and RMS > 0. Health check = in-meeting text **AND** `audio count >= 1` **AND** sink RMS > 0 (a "reload+rejoin" heal ladder belongs in the watchdog, see below).
- **False `ENDED` flag (2026-09-17).** The scraper writes `run/ENDED` whenever the client UI momentarily disappears — which includes your own reload/leave/rejoin. After any reload, rejoin or lane surgery: `rm -f run/ENDED` and re-verify, or the monitor/wrap-up cron finalizes a meeting that is still running and the "attend till the end" promise dies silently.
- **An `ENDED` flag can also be simply wrong, not just premature — cross-check the audio (2026-09-17).** Same lane: flag `16:11:12`, captions dead after `15:30:57` (7 lines), yet the mono audio lane held live speech until `16:17:48` and the enrolment Q&A was inside that window. Before writing "meeting ended at H:MM", measure the tail segments (`volumedetect`, `mean_volume ≈ -87 dB` = nobody there) — the flag is a hint, the waveform is the evidence.
- **A previous run's notes/README/label file is not a source of truth for THIS session.** `run/label.txt`, `source-url.txt` and any `NOTES-*.md` left by an earlier lane describe the *earlier* meeting; carried-forward names and topics read as current fact and produce a confidently wrong brief (2026-09-20: wrong host, wrong session framing). Bind the brief to the lane's own `run/label.txt` + the chunk header timestamps, and re-verify attendee-facing facts (host, title, date) from an external artifact.
- **ASR captions/transcripts are the wrong place to read numbers and names (2026-09-17).** Whisper heard "Seattle" for Salesforce, "cupartinos" for Kubernetes, "you scheme a Chinese model" for Moonshot, "kin k2.5" for Kimi K2.5, and "80,000 rupees" where the slide showed 18,000 (₹ is often rendered as "one like"); the same transcript contradicts itself on price. Prose, argument flow and *spoken* technical claims come from the transcript; **every figure, model id, bucket, URL or product name that will be quoted comes from OCR of a screenshot or from a file on disk** — `shots-ocr/*.txt` next to the run makes that check cheap.
- **Read `.disabled`, not the class.** A Join button can carry a `disabled` class with `disabled === false` (and the reverse): check the property inside the frame before declaring the join flow broken.
- **Measure level with `parec` + struct RMS**, per sink: `parec --device=<sink>.monitor --rate=16000 --channels=1 --format=s16le` → `struct.unpack('<%dh', buf)` → RMS/peak. One probe answers "is this sink actually carrying audio", works per-device, and needs no `audioop` (gone in 3.13 — do the maths in plain Python).
- **JS clicks are untrusted**: `element.click()` grants no user activation and cannot unblock autoplay/gesture-gated audio — use a real CDP click (`Input.dispatchMouseEvent`, helper `t.click(x, y)`). Toolbar buttons that render only on hover, or whose box sits outside the viewport, silently miss.
- **Never echo a Zoom web-client tab's `location.href`** — it contains the join `tk=` bearer token and ends up in tool output, logs and context. Read it redacted only.
- **Check the input side before promising a voice answer**: `ls /dev/snd` + `pactl list sources short` — a headless VM that only has a null sink (`auto_null.monitor`) has **no capture source at all**, so a live spoken reply is not a fallback you can offer. Say that in one line rather than implying you could speak if asked.
- **A huge caption log read whole can come back elided/empty.** Never treat the empty result as "no content" — dedupe and slice it in code (`scripts/dedupe_captions.py`, window by window) before drawing any conclusion about the meeting.
- **Background guards can murder a live meeting tab (2026-09-17).** `~/ops/scripts/chrome_tab_guard.py` runs every 5 min and closes tabs by rule (duplicate URL / idle-past-soft-cap). A meeting URL never changes, so it looks idle and gets closed mid-session. Fix BEFORE joining: add the meeting URL to `~/ops/chrome_tab_guard_keep.txt` (keep-list), and re-run the guard with `--dry-run --verbose` to prove the tab is protected.
- **systemd-oomd and OOMScoreAdjust (2026-09-17).** `user@1000.service` carries `ManagedOOMMemoryPressure=kill`, so a memory spike during a 2-core meeting can kill Chrome/whisper; the capture units were also `OOMScoreAdjust=200` (kernel OOM picks them first). Drop-in on every capture unit: `ManagedOOMPreference=avoid`, `OOMScoreAdjust=0`, plus `Restart=always` (+`RestartSec`) — a *clean* ffmpeg exit otherwise ends the capture for good.
- **Recorder segment naming (2026-09-17).** `-y ... live_%03d.wav` is a data-loss trap: a unit restart restarts numbering at 000 and OVERWRITES `live_000.wav`. Use `-strftime 1` with `live_%%Y%%m%%d-%%H%%M%%S.wav` in the unit (double `%%` because systemd expands `%` first) and confirm the real argv with `systemctl --user show <unit> -p ExecStart`.
- **The watchdog should HEAL, not just alert.** Keep the monitor output stable while healthy (hash-suppressed cron only fires on change), and let it act: if the meeting tab vanishes while LIVE, re-open the stored join URL + re-run the in-meeting setup, throttled to 1 attempt / 5 min and logged to `run/heal.log`. Report an ENDED state with: transcribe leftover segments, write notes, list infra actions.

### 2026-09-18 field notes (passcode links, captions toggle, non-English ASR, chat gap)

Detail lives in `~/ops/zoom-attend/README-runbook.md` pitfalls 15-20; the short version:

- **`/j/<id>?pwd=...` links:** the interstitial URL is NOT `app.zoom.us/wc/<id>`, so `open_join.py`'s tab-key check fails. Join in the browser first via `join3.py open` → `wcui_frame.py <mn> - click "^Join from browser$"` → `wcui_frame.py <mn> <mn>/join fill 0 "<name>"` → `click "^Join$"`, then start the lane with `start.sh "<url>" "app.zoom.us/wc/<mn>" "<label>" --no-open` (without `--no-open` a SECOND tab is opened and `scrape.py` may bind the preview tab). `open_join.py` now reuses a matching tab and completes the join itself, so the TAB=GONE heal works on pwd links too.
- **`ZOOM_FRAME` is mandatory** (`<mn>/join`, the `webclient` iframe) — without it the scraper logs `frame NOT found` and captures zero captions. `start.sh` derives `ZOOM_TAB_KEY/ZOOM_FRAME/ZOOM_RUN/ZOOM_LABEL/ZOOM_LANG` + `<run>/lang.txt`.
- **Captions are OFF by default** in the web client: open the `More` overflow menu and click the `Show Captions` item (menu entries are DIVs, not buttons, so the frame click matcher now includes `[role=menuitem],div,span,li`). Rendering captions = `.live-transcription-subtitle__*`.
- **Non-English sessions:** whisper.cpp defaults to `-l en` and answers `(speaking in foreign language)` for every segment. Set `ZOOM_LANG=ur` (writes `<run>/lang.txt`, which both transcriber scripts prefer) — ggml-base is multilingual. Budget ~6 min per 5-minute chunk on this VM; drain the rest after `ENDED` with `ZOOM_CPUS=0,1`.
- **Repetition loops are a whisper failure mode, not content** (one Urdu chunk repeated a phrase 40x): run whisper with `-mc 0` and collapse repeats (`ws_seg.sh` + `collapse_repeats()` in both transcriber scripts).
- **Never run the backlog-drain timer during a live lane** — it sweeps every `run*` dir, launches a second single-core whisper on an archived lane and drives a 2-core VM to load ~10, starving Chrome/recorder. Stop it at lane start, drain once after `ENDED`, restart after.
- **Prove chat capture, don't assume it:** a QA session with 50-63 unread chat messages produced an EMPTY `chat.txt` while the scraper still logged `chat-open`. Check the chat unread badge against `chat.txt` size early; the panel is now found via its composer (textarea/input with a "type message" placeholder) with a diagnostic `chat meta:` log line — validate on the next live session.
- **`pkill -f <script>.py` kills the caller**: the pattern matches your own `bash -c` command line (hit twice). Kill by PID or `ps`+`awk`.
- **The audio-track heal can drop a live meeting**: it reloads the tab, and a reload of a `ref_from=launch` URL lands on the pre-join preview. Only trust `TRACKS=0` when the frame still shows in-meeting UI, and cross-check any `ENDED` flag against the waveform of the last segments (a real end = post-meeting segments at ≈ -90 dB) before declaring the meeting over.
- **One notes producer per lane:** the generic watch cron and a meeting-specific notes cron both fire on `ENDED` and duplicate work/messages. Keep one; the generic job now takes a cheap path when `run/NOTES-*.md` already exists.

### 2026-09-18 second session (REGISTRATION links, no-captions webinar, modal-blocked shots)

- **`/meeting/register/<id>` links (registration JWT):** fill `First Name` / `Last Name` / `Email` (React-safe native-setter + `input` event) → click `Register and Join` → Zoom lands on `https://us06web.zoom.us/w/<mn>?tk=…&pwd=…` with `#success`.
